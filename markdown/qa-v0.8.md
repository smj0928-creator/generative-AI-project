> 작성일: 2026-11-24  
> 테스트 기준: [v0.8 PRD](prd.md#v08--운동-달력과-친구-초대) · [배포본](https://smj0928-creator.github.io/generative-AI-project/) · 저장소 커밋 `3d4f0d2`  
> 문서 상태: **테스트 설계 완료, 일부 화면 동작은 사용자 구두 보고로 확인**. 케이스별 재현 조건과 DB 증거는 아직 기록되지 않았다. 아래의 `미실행`은 통과를 뜻하지 않는다.

## 1. 목적과 범위

사용자가 실제로 앱을 쓰는 순서에 따라 **비회원 탐색 → 계획 생성 → 운동 완료 → 회원 로그인과 데이터 복원 → 달력 → 친구 초대**를 검사한다. 기능이 눌리는지만 보지 않고 화면 안내, Supabase 저장 값, 오류 상태까지 확인한다.

최신 v0.8 PRD를 판정 기준으로 사용한다. 예를 들어 이전 v0.2 기록에는 참고사항을 추천에 반영하는 요구가 있지만, v0.8의 FR-08-04는 **참고용 메모가 계획을 바꾸지 않음을 명시**하도록 정한다. 또한 현재 주간 목록은 **내 운동**에 있고 홈에는 **다음 운동**을 보여 준다. 이전 버전의 화면 배치를 현재 버전의 합격 기준으로 쓰지 않는다.

### 팀별 확인 역할

|---|---|

| ChatGPT | 테스트 항목 초안과 PRD 연결 정리. 실제 판정은 팀원이 수행 |

## 2. 실행 준비와 기록 방법

### 2026-11-24 팀의 화면 확인 보고

아래는 사용자가 직접 확인했다고 알려 준 동작이다. 실행 영상·화면 캡처·DB 행을 이 문서에 첨부한 결과는 아니므로, 케이스 표의 전체 합격 판정과 구분한다. 실행자를 최유찬으로 임의 표기하지 않는다.

| 흐름 | 사용자 보고 내용 | 연결 케이스 | 아직 필요한 확인 |
|---|---|---|---|
| 비회원 탐색 | 로그인하지 않아도 홈과 운동 목록을 볼 수 있고, **함께** 기능은 사용할 수 없다 | G01·G02·G03 | 공개 루틴의 상세 항목, 로그인 안내 문구를 같은 조건에서 재현 |
| 계획·가이드 | 선택한 조건에 맞는 계획이 나오며 운동 사진도 표시된다 | P01·P02·P06 | 장소·방식 조합별 비교, 안전 안내와 사진 출처 확인 |
| 완료·달력 | 운동 완료 상태와 달력 표시가 연동된다 | P07·C01 | 완료 시각과 날짜, 완료 취소 후 갱신까지 확인 |
| 비회원 저장 규칙 | 비회원의 회원 기록이 Supabase에 생기지 않아야 한다 | G04 | 새로고침 후 로컬 유지와 `user_plans`·`workout_logs`의 게스트 행 부재를 실제 조회 |

**현재 결론:** 화면의 주요 흐름은 사용자 보고상 정상이다. 비회원의 Supabase 미저장은 기대 동작이며, DB를 조회해 확인한 결과로 기록하지 않는다.

1. [배포본](https://smj0928-creator.github.io/generative-AI-project/)의 표시 버전과 저장소 커밋을 기록한다. 테스트 중에는 같은 버전을 사용한다.
2. 모바일 크기 화면 1개와 키보드를 쓸 수 있는 데스크톱 브라우저 1개를 준비한다. 게스트용 새 브라우저 프로필과 회원 A·B용 서로 다른 프로필을 사용한다.
3. 회원 A·B는 **테스트 전용 계정**으로 준비한다. 비밀번호, 인증 링크, 비밀 키는 이 문서나 캡처에 남기지 않는다. 두 계정의 `user_id`는 담당자가 비공개 테스트 기록에만 적는다.
4. 기본 입력값: 체력 향상 / 입문 / 주 3회 / 20분 / 홈트레이닝 / 맨몸운동. 다른 조건이 필요한 경우 각 항목에 따로 적는다.
5. Supabase의 `user_plans`, `workout_logs`, `friend_profiles`, `friend_requests`는 테스트 계정의 행만 확인한다. 화면 캡처와 DB 행의 식별자·시각은 개인정보를 가리고 보관한다.
6. 각 테스트의 결과를 `통과 / 실패 / 미구현 / 미실행 / 보류` 중 하나로 기록한다. 실패 시 재현 절차, 실제 결과, 화면·DB 증거를 남긴다. 수정 후에는 같은 입력으로 다시 실행한다.

**우선 시연할 12건:** G01, G02, G03, P01, P04, P06, A01, A04, A05, C01, F02, F03. 나머지는 예외·보안·회귀 확인에 사용한다.

## 4. 사용자 과업 관찰

최유찬이 목표 사용자에게 사용 방법을 먼저 설명하지 않고 아래 과업을 준다. 각 과업마다 **도움 없이 완료 / 도움받아 완료 / 미완료**, 걸린 시간, 멈춘 화면, 사용자의 말과 사후 인터뷰 이유를 구분해 기록한다. 한 사람이 여러 번 수행하면 익숙해진 효과를 표시한다.

| 과업 ID | 사용자에게 줄 과업 | 관찰할 지점 | 연결 QA |
|---|---|---|---|
| U01 | 로그인하지 않고 오늘 따라 할 만한 공개 루틴을 찾아보세요 | 공개 루틴 발견, 구성 이해, 로그인 요구 여부 | G01·G02 |
| U02 | 자신의 조건으로 주간 운동 계획을 만들고 첫 운동을 완료해 보세요 | 장소·방식 선택 이해, 상세·안전 안내, 완료 후 다음 화면 | P01·P02·P06·P07 |
| U03 | 로그인 후 자신의 운동 기록이 남았는지 확인해 보세요 | 로그인 오류 이해, 달력 발견, 기록 복원 기대 | A01·A04·C01 |
| U04 | 친구에게 초대 코드를 보내고 요청을 수락해 보세요 | 코드 위치, 두 계정의 역할 이해, 요청 새로고침과 수락 | F01·F02·F03 |

**관찰 기록:** 참여자 ID(실명 대신 코드) / 과업 ID / 시작·종료 시각 / 완료 상태 / 도움 횟수 / 실제 행동 / 사용자 발언 / 팀의 원인 추정 / 개선 후보. 관찰 사실과 원인 추정을 섞지 않는다.

**AI 품질평가 범위:** v0.8 계획 생성은 규칙 기반이다. 생성형 AI 출력의 정확성·일관성을 실제로 평가했다고 기록하지 않는다. 대신 조건별 계획 구성과 안전 안내를 P02·P03·P06에서 확인한다.

### 발표 전에 최소 확인할 결론

- 회원의 계획·완료 기록이 **Supabase DB에 실제로 저장되고**, 재접속·다른 기기에서 복원되는가?
- 비회원의 기록은 브라우저 저장이며 친구 기능을 사용할 수 없다는 점을 설명할 수 있는가?
- 두 계정의 친구 요청·수락·삭제와 공개 범위가 실제로 작동하는가?
- 계획 생성은 현재 규칙 기반이며 생성형 AI 호출이 없다는 점을 정확히 밝히는가?

이 네 항목 중 미검증이 있으면 발표에서 **구현 / 화면 확인 / 실사용 미검증**을 구분해 말한다.
