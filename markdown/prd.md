## v0.1 — 기존 프로토타입

> **제품 버전:** 0.1  
> **상태:** 기존 프로토타입 기준본  
> **기준:** 저장소의 v0.1 프로토타입과 현재 보존된 와이어프레임  
> **용도:** v0.2 이후 버전과 비교·발표하기 위한 이전 버전 기록

### 1. 제품 개요

AI트레이너 v0.1은 사용자가 운동 목표와 수준, 주당 운동 횟수, 1회 운동 시간 및 주의사항을 입력하고 주간 운동 계획과 완료 기록을 확인하는 모바일 웹 프로토타입이다. 운동 계획은 미리 준비된 템플릿과 규칙으로 구성된다. 실제 생성형 AI, 계정 로그인, 서버 저장은 연결되어 있지 않으며 데모 기록은 브라우저의 `localStorage`에 저장된다.

### 2. 대상 사용자와 문제

- 운동을 처음 시작하거나 꾸준한 운동 습관을 만들고 싶은 사람
- 목표와 현재 수준에 맞는 주간 운동 계획을 간단히 확인하고 싶은 사람
- 완료 기록과 성취 피드백으로 운동 진행 상황을 관리하고 싶은 사람

초보 사용자는 운동 계획을 직접 구성하기 어렵고, 계획을 세운 뒤에도 주간 진행 상황과 성취를 한곳에서 확인하기 어렵다.

### 3. 핵심 사용자 흐름

1. 시작 화면에서 둘러보기 또는 다음을 눌러 앱에 진입한다.
2. 홈에서 운동 목표, 수준, 주당 횟수, 운동 시간과 주의사항을 입력한다.
3. 주간 계획을 생성하고 홈 또는 플랜 화면에서 요일별 운동을 확인한다.
4. 운동 상세와 기본 안전 안내를 살펴본다.
5. 운동 완료를 기록하고 성장 화면에서 진행률과 배지를 확인한다.
6. 함께 화면에서 데모 리그와 공개 루틴을 살펴보고, 설정에서 닉네임을 저장한다.

### 4. 기능 범위

| 기능 | v0.1 기준 |
|---|---|
| 운동 조건 입력 | 목표, 수준, 주당 운동 횟수, 운동 시간, 주의사항 입력 |
| 주간 계획 | 목표별 사전 정의 운동 템플릿을 이용한 규칙 기반 계획 생성 |
| 운동 상세 | 운동 구성과 기본 안전 안내 표시 |
| 완료 기록 | 운동 완료 상태와 진행 현황 저장 |
| 성장 | 완료 횟수, 주간 진행률, 누적 기록 및 배지 표시 |
| 준비 체크리스트 | 운동 준비 항목 체크 및 브라우저 내 저장 |
| 함께 | 가상 리그 순위, 승급 조건, 공개 루틴과 매칭 데모 표시 |
| 설정 | 닉네임 저장, 데모 기록 초기화 |
| 저장 | 동일 브라우저의 `localStorage`에 데이터 저장 |

### 5. 화면 구조

하단 탭 기준으로 홈, 플랜, 성장, 함께, 설정 화면을 제공한다. 시작 화면과 운동 상세는 주요 화면에서 이어지는 흐름으로 제공한다.

### 6. 비범위 및 한계

- 실제 생성형 AI 모델/API를 통한 추천
- 실제 회원가입, 로그인, 계정 인증 및 기기 간 데이터 동기화
- 서버 데이터베이스, 실시간 사용자 순위와 멀티플레이
- 실제 트레이너 인증, 푸시 알림, 의료적 평가나 운동 처방

리그와 매칭은 시연용 데이터다. 운동 안전 안내는 기본 정보이며 의료 또는 전문 처방을 대체하지 않는다.

### 7. 완료 기준

- 운동 조건을 입력하고 주간 계획을 확인할 수 있다.
- 운동 상세와 기본 안전 안내를 확인할 수 있다.
- 완료 기록에 따라 성장 화면 정보가 갱신된다.
- 닉네임과 주요 데모 기록이 같은 브라우저에서 유지된다.
- 실제 AI·로그인·서버 기능이 연결되지 않았다는 점을 명확히 알린다.

## v0.2 — 피드백 반영 와이어프레임

> **제품 버전:** 0.2  
> **상태:** 설계 초안 — 와이어프레임 화면과 문구 확정 후 검토  
> **기준:** v0.1 와이어프레임과 사용자가 제공한 개선 피드백  
> **이전 버전:** 이 문서의 [v0.1](#v01--기존-프로토타입)

### 1. 제품 방향

AI트레이너 v0.2는 운동 초보가 자신의 조건과 피하고 싶은 부위를 입력하고, **그 조건을 반영한 시연용 주간 계획**을 확인하는 과정을 중심에 둔다. 첫 접속에서는 빈 기록에 맞는 안내를 보여 준다. 운동 상세의 안전 안내는 항상 보인다. 완료 기록과 성장은 핵심 흐름을 뒷받침한다.

v0.2 와이어프레임의 계획 생성은 **규칙 기반 시연**이라고 표시한다. 화면과 이 문서는 향후 AI가 들어갈 위치, 입력값, 출력과 실패 시 대체 경로를 설명한다. 실제 LLM 연동은 서버 또는 프록시가 준비된 프로토타입 개발 단계에서 구현한다. 정적 페이지에는 API 키를 저장하지 않는다.

### 2. 대상 사용자와 핵심 흐름

- **대상:** 자신에게 맞는 계획을 쉽게 시작하고 싶은 운동 입문자
- **문제:** 계획이 자신의 목표와 주의 부위를 반영하는지 알기 어렵고, 처음부터 순위가 보이면 실제 기록으로 오해할 수 있다.
- **핵심 흐름:** 첫 사용 안내 → 운동 조건 입력 → 주의 부위 선택 → 계획 생성과 근거 확인 → 상세 및 안전 안내 → 운동 완료 → 성장 기록 확인

### 3. 범위와 우선순위

| 구분 | 범위 |
|---|---|
| Must | 조건 입력·반영, 안전 필터와 상한 설계, 주간 계획과 근거, 운동 상세의 상시 안전 안내, 첫 사용 빈 상태, 완료 기록 |
| Should | 향후 AI 요청·응답·오류·대체 경로의 설계 설명, 접근 가능한 하단 메뉴, 안내 문구 정리 |
| Later | 실시간 리그, 배지 확대, 공개 트레이너 루틴, 유사 친구 매칭, 푸시 알림 |

v0.1의 리그·배지·친구 화면은 비교 발표용 v0.1에만 보존한다. v0.2 화면에서는 제공하지 않고 프로필의 '다음 단계' 안내로만 설명한다. 동작하지 않는 알림 토글은 제거한다. 로그인·전화번호 입력은 v0.2 범위에서 제외하고 닉네임만 사용한다. 하단 메뉴는 **홈·플랜·기록·프로필** 네 가지다.

### 4. 화면과 상태

| 화면/상태 | 주요 내용 | 동작 또는 예외 | 우선순위 |
|---|---|---|---|
| 첫 진입·홈 | 데모 안내를 한 번 보여 주고 '계획 만들기부터 시작해요' 안내 표시 | 활동 0회·XP 0; 이후 접속에는 안내 반복 없음 | Must |
| 운동 조건 | 목표, 수준, 주당 횟수, 시간, 주의 부위 선택(무릎·허리·어깨·없음), 선택적 추가 메모 | 선택값을 계획 요약·생성 요청에 포함 | Must |
| 계획 생성 | 규칙 기반 시연 결과와 향후 AI 연결 지점 표시 | 계획의 입력 조건·제외/조정된 동작·현재 생성 방식을 표시 | Must |
| 주간 계획 | 요일별 운동, 시간·강도, 선택한 주의 부위 반영 설명 | 운동 상세로 이동 | Must |
| 운동 상세 | 준비 항목, 동작과 횟수, 항상 보이는 안전 안내 | 통증·어지러움 시 중단 및 전문가 상담 안내, 완료 기록 | Must |
| 기록 | 완료 횟수·주간 달성률·XP | 처음에는 0 기록에 맞는 안내, 완료 후 값 갱신 | Must |
| 프로필 | 닉네임·데모 초기화·향후 기능 안내 | 전화번호·작동하지 않는 토글·리그 순위 없음 | Should |

### 6. AI 생성 설계

#### 입력과 출력

| 항목 | 예시 | 용도 |
|---|---|---|
| 목표·수준 | 근력 강화·초보 | 목표와 입문자 강도 상한 결정 |
| 주당 횟수·회당 시간 | 주 3회·20분 | 일정과 운동 분량 제한 |
| 주의 부위 | 무릎 | 부담 동작 제외·대체 |
| 추가 메모 | 계단 운동을 피하고 싶음 | 서버가 해석 가능한 경우에만 반영; 미지원이면 그 사실을 알림 |

**프롬프트 예시(서버 내부):** “사용자는 운동 초보이며 근력 강화를 원한다. 주 3회, 회당 20분으로 계획을 작성한다. 무릎 부담 동작을 제외하고 저강도 대체 동작을 제시한다. 각 운동의 시간·세트·안전 주의와 제외 근거를 JSON으로 반환한다. 의학적 진단이나 치료를 제안하지 않는다.” 실제 구현에서는 사용자 입력을 검증하고 프롬프트와 응답을 서버에서 처리한다.

**기대 출력 형식 예시:**

```json
{
  "source": "ai",
  "days": [{ "day": "월", "title": "저충격 전신 루틴", "minutes": 20, "intensity": "입문", "exercises": [{ "name": "벽 푸시업", "sets": 2, "reps": 8 }] }],
  "adjustments": ["무릎 부담 동작 제외"],
  "safetyNote": "통증이나 어지러움이 있으면 중단하고 전문가와 상담하세요."
}
```

**향후 실제 AI 연동 시 처리 순서:** 화면에서 조건 수집 → 서버/프록시에서 입력 검증 → LLM 요청 → 응답 형식 검증 → 금기 동작 필터 및 강도 상한 재검사 → 계획 표시. 요청 실패·시간 초과·검증 실패에는 규칙 기반 계획을 대체 수단으로 사용하고 출처를 표시한다. 대체 계획도 안전 필터를 통과해야 한다. 정적 GitHub Pages에는 키를 넣지 않는다. 현재 v0.2 와이어프레임에서는 안전 규칙을 적용한 데모 결과만 생성한다.

**안전 문구 참고:** [CDC의 운동 시작 안내](https://www.cdc.gov/healthy-weight-growth/physical-activity/getting-started.html)는 천천히 시작해 강도를 점차 높이고 만성 질환이 있다면 의료진과 적절한 운동을 상의하도록 안내한다. [NHS 병원의 운동 안전 안내](https://www.cuh.nhs.uk/patient-information/home-exercise-programme/)는 운동 중 통증·불편이 심해지거나 어지러우면 중단하고 의료진의 조언을 구하도록 안내한다. 이 근거는 일반적인 중단·상담 문구를 위한 것이며, 개별 동작의 적합성을 보증하지 않는다.

### 8. 데이터·접근성·문서

- **데이터:** 선택한 부위·운동 조건·완료 기록·닉네임은 이 브라우저에만 저장되며 내 정보에서 초기화할 수 있다. 실제 계정, 전화번호, 질환·진단 정보의 자유 입력은 받지 않는다.
- **상태:** 와이어프레임에서는 초기·생성 완료·안전 검토 필요 상태를 구분한다. 실제 AI 연결 시에는 생성 중·규칙 기반 대체 계획 상태도 화면 읽기용 메시지와 함께 추가한다.
- **접근성:** 모바일 키보드와 물리 키보드에서 입력·탭·버튼이 동작하고 포커스가 보인다. 메뉴는 기호만으로 이름을 전달하지 않는다.
- **문서:** README는 저장소명과 실제 폴더 구조, Pages 링크, 스크린샷을 반영한다. 업로드 안내에는 루트 파일뿐 아니라 `css`, `js`, `data` 등 필요한 폴더 전체를 포함한다.
